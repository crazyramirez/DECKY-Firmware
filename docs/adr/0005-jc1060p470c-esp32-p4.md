# ADR 0005 — Port to the Guition JC1060P470C: ESP32-P4, MIPI-DSI, 1024×600 UI

Status: accepted (firmware 0.10.0). Supersedes the board-specific parts of ADR 0004 (NV3041A QSPI
driver, 480×272 layout, IO17/IO18 sleep button, deep sleep). The stack (Arduino-ESP32 3.3.5 /
ESP-IDF 5.5.1 via pioarduino 55.03.35, LVGL 8.4.0) is unchanged.

## Context

The deck moves from the 4.3" JC4827W543 (ESP32-S3, 480×272 QSPI) to the 7" **JC1060P470C**:
ESP32-P4 (no radio, 32 MB PSRAM, 16 MB flash) + ESP32-C6 as the Wi-Fi co-processor over
ESP-Hosted/SDIO, 1024×600 IPS with a **JD9165** MIPI-DSI controller, GT911 touch. Sources: the
vendor LVGL demo (`pins_config.h`: LCD RST 5, touch SDA 7 / SCL 8, TP_INT and TP_RST −1) and the
JC1060P470C CryptoTracker firmware by the same author, which runs on this board with the same
platform version (display, touch, backlight GPIO23, Wi-Fi through `WiFi.h`, BOOT on GPIO35,
console notes).

## Decisions

1. **One board per repository** (as in ADR 0004). The repository continues the JC4827W543 history;
   firmware 0.10.0 is the first JC1060P470C build.
2. **Display:** ESP-IDF's DSI/DPI driver with Espressif's `esp_lcd_jd9165` (vendor init sequence,
   kept unmodified in `firmware/lib/esp_lcd_jd9165`, Apache-2.0): 2 data lanes at 750 Mbps, DPI
   52 MHz (~60 Hz with the vendor timings), D-PHY supplied by the P4's internal LDO channel 3 at
   2.5 V, one RGB565 frame buffer in PSRAM scanned continuously.
3. **LVGL 8.4 kept, partial mode:** two 40-line band buffers in internal RAM; `flush_cb` hands each
   band to `esp_lcd_panel_draw_bitmap`, which copies it with the **DMA2D** engine; the completion
   ISR only gives a semaphore and LVGL's `wait_cb` takes it before reusing the buffer (no LVGL call
   from an ISR). Direct mode into the scanned buffer was rejected: rendering into PSRAM through the
   cache is slower than into internal RAM and needs manual cache write-backs. Moving to LVGL 9 (as
   the CryptoTracker does) would mean rewriting every screen for no user-visible gain.
   `LV_COLOR_16_SWAP=0`: the frame buffer is native little-endian RGB565, so the coin logos are
   regenerated little-endian, the chart rasteriser byte-swaps only when LVGL does, and album art
   (big-endian in protocol v1, unchanged for the other decks) is swapped on arrival.
4. **UI scale ×1.5, extra room to the content.** 1024×600 at ~170 dpi vs 480×272 at ~128 dpi: a
   uniform ×2.13 would fill the screen with the 4.3" layout but make text kiosk-sized (34 px body);
   ×1.5 keeps type close to the 4.3" physical size plus a margin for desk viewing distance (body
   24 px ≈ 3.6 mm) and leaves room for more content. Every pixel literal of the 480×272 layout was
   scaled ×1.5 (fonts regenerated at 15/18/21/24/30/42/60 px and a 78 px clock); metrics derived
   from `kContentW/H` follow the real screen; pages with hand-placed parts (Player, Today, coin
   detail, coin picker, setup assistant) were re-laid out to use the space. Every page is checked
   in the desktop simulator at 1024×600.
5. **Touch:** GT911 polled over I²C (SDA 7 / SCL 8, 400 kHz). INT and RST are not wired, so there is
   no reset/address-select sequence: 0x5D and 0x14 are probed; coordinates are scaled from the
   controller's configured resolution as before.
6. **Power without deep sleep.** No line can wake the P4 from deep sleep on this board (the touch INT
   is not wired; BOOT is GPIO35, not an LP GPIO; there is no IO17/IO18 header button). *Auto sleep*
   and *Turn off screen* switch the backlight off and stop band copies; any touch (swallowed) or
   the BOOT button turns the screen back on, BOOT also turns it off.
7. **USB console on USB-Serial/JTAG without HWCDC.** The CryptoTracker found Arduino's HWCDC TX
   interrupt faulting on the P4's USB-Serial/JTAG FIFO under load, so `ARDUINO_USB_CDC_ON_BOOT=0`.
   Logs use the ESP-IDF console (UART0 + USB-Serial/JTAG secondary output) with
   `USE_ESP_IDF_LOG` and `LOG_LOCAL_LEVEL=ESP_LOG_INFO` (the prebuilt sdkconfig caps logs at ERROR,
   so the level is raised at runtime); `src/board/usb_console` installs the IDF USB-Serial/JTAG
   driver for input (its TX interrupt only runs when the driver itself writes: command answers and
   `shot`).
8. **Flash layout:** 16 MB, `partitions.csv` with two 7 MB app slots (OTA-ready, unused for now),
   NVS 20 KB, coredump. The P4 bootloader is at `0x2000`; merged images still start at `0x0`.
9. **Silicon revisions:** `deck` targets ESP32-P4 v1.x (every JC1060P470C shipped so far,
   `esp32-p4-evboard`), `deck_r3` targets v3.x (`esp32-p4_r3`); the binaries are not interchangeable.

## Consequences

- Flash use ≈ 2.9 MB of the 7 MB slot (fonts ≈ 1.6 MB at the new sizes, 54 coin logos at 36/48 px).
- Wi-Fi depends on the ESP32-C6 running a compatible ESP-Hosted slave firmware (as shipped).
- Items that need the physical board are tracked in [HARDWARE_VALIDATION.md](../HARDWARE_VALIDATION.md)
  (colours and orientation, touch mapping and address, Wi-Fi through the C6, frame rate, console).
